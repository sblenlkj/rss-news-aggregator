# Приёмочный сценарий: две публикации в тестовый RSS и проверка поиска

> **Учебные вымышленные новости.** Это не реальные сообщения СМИ. Публикуем их вручную через интерфейс или Swagger, проверяем RSS → парсер → SQLite → персональные фильтры → поиск. Никакого seed-скрипта.

## Подготовка

1. Запусти сервер: `uv run uvicorn news_aggregator.main:app --port 8000`.
2. Открой http://127.0.0.1:8000/ и раскрой **«Тестовый RSS · опубликовать новость»**; либо Swagger http://127.0.0.1:8000/docs → `POST /api/v1/test-feed/articles`.
3. Опубликуй **обе** новости ниже **один раз**. Каждая публикация получает свой UUID, поэтому повторный POST создаст новую запись, а не заменит прежнюю.
4. Нажми **«Обновить»** у `http://127.0.0.1:8000/test-feed/rss.xml` (или вызови `POST /api/v1/sources/{source_id}/refresh`). Публикация в тестовую ленту **сама по себе не добавляет статью в SQLite**.
5. Проверь через `GET /api/v1/articles`, что обе статьи появились. Можно уточнить `?source_id=<UUID тестового RSS>`.
6. Создай/выбери пользователя и **отметь только тестовый RSS** в подписках. Так результаты не смешаются с новостями Хабра, РИА и МК. Сохранять фильтры необязательно: «Найти новости» берёт текущие значения формы.

Если в `data/test_feed.json` уже есть старые публикации, они также будут доступны; ниже ожидаемые количества предполагают, что по тестируемым словам старые статьи не совпадают. Для абсолютной изоляции используй необычные словосочетания в заданиях.

## Публикация №1 — ИИ и беспилотная авиация

**Назначение:** отличить `summary` от `content`; проверить BM25 по слову внутри `content`, лемматизацию и смысловую тему.

```json
{
  "title": "Инженеры испытали беспилотный самолёт с нейросетевым автопилотом",
  "summary": "В учебном эксперименте прототип летательного аппарата самостоятельно выбирал безопасную траекторию.",
  "content": "Команда разработчиков создала беспилотник для мониторинга лесов. На борту работает нейросеть, которая распознаёт препятствия и помогает самолёту менять маршрут. Для планирования полёта используется трансформер. Испытания показали, что автономная система может вести воздушное судно без постоянного управления оператором. Кодовое название испытания — аэрокварц.",
  "tags": ["авиация", "искусственный интеллект", "робототехника"]
}
```

**Контроль:** слово `аэрокварц` находится **только в content** и позволяет проверить индексацию этого поля; `беспилотный`, `самолёт`, `нейросеть` и `трансформер` — другие проверочные термины.

## Публикация №2 — медицина и анализ снимков

**Назначение:** отличить тематически похожую статью от статьи про самолёты; проверить морфологию, теги и семантический поиск.

```json
{
  "title": "Врачи испытали систему анализа медицинских снимков",
  "summary": "Экспериментальная программа помогает специалистам находить изменения на рентгеновских изображениях.",
  "content": "Исследователи медицинского центра протестировали алгоритм компьютерного зрения для анализа снимков лёгких. Система оценивает изображения и выделяет участки, требующие внимания врача. Программа не ставит диагноз самостоятельно: окончательное решение принимает специалист. В отчёте испытания использовался условный термин медикварц.",
  "tags": ["медицина", "диагностика", "компьютерное зрение"]
}
```

**Контроль:** `медикварц` встречается **только в content**, `диагностика` — в тегах, `врачи` — в заголовке. Слово `самолёт` отсутствует.

## Поисковые эксперименты

Проводить по очереди, выбирая **только тестовый RSS**. В поле **«Ключевые слова»** указывай одну строку на отдельный OR-фильтр. Для строгих проверок сначала **отключи Navec**, чтобы автоматическое расширение не добавляло другие слова. Выбирай «Только слова» (BM25), лимит 20, дату оставь пустой.

| № | Ключевые слова | Режим / Navec | Что проверяем | Ожидание при двух опубликованных статьях |
| --- | --- | --- | --- | --- |
| 1 | `аэрокварц` | Keyword / выкл. | Поле `content` участвует в индексации | Только статья №1 |
| 2 | `медикварц` | Keyword / выкл. | Другой `content` | Только статья №2 |
| 3 | `самолёт` | Keyword / выкл. | Совпадение с заголовком/текстом | Статья №1 |
| 4 | `врач` | Keyword / выкл. | Лемматизация: `врачи` → `врач` | Статья №2 |
| 5 | `диагностика` | Keyword / выкл. | Индексация `tags` | Статья №2 |
| 6 | `аэрокварц` и `медикварц` **на разных строках** | Keyword / выкл. | OR между фильтрами | Обе статьи, каждая со своим совпадением |
| 7 | `космический лифт` | Keyword / выкл. | Отрицательный тест | Совпадений не ожидается |

### Проверка Navec

1. Введи `самолёт` и нажми **«Посмотреть расширение Navec»**. Предпросмотр не требует выбранного RSS: он показывает ближайшие слова из частотного словаря модели.
2. Переключи галочку Navec и повтори Keyword-поиск по `самолёт`; сравни `matched_terms` и `expanded_terms` в блоке «Почему новость найдена».
3. Повтори для `медицина` и `автомобиль`.

**Важно:** Navec выдаёт *семантически близкие слова*, а не гарантированные синонимы. При фактическом поиске расширение ограничено словами **выбранных статей**, и применяется порог cosine 0.55, максимум пять добавлений. Поэтому отсутствие новых совпадений или пустое `expanded_terms` **не означает ошибку**. Предпросмотр и итоговый набор терминов могут отличаться.

### Проверка Semantic (GigaChat Embeddings + Qdrant)

Очисти ключевые слова (не обязательно, если выбран режим **«Только семантика»**); укажи **«Семантический запрос»**:

| Тема | Ожидаемая близость по смыслу |
| --- | --- |
| `Автономный летательный аппарат обходит препятствия во время полёта` | Выше к статье №1 |
| `Врачи используют компьютерное зрение для анализа рентгеновских снимков` | Выше к статье №2 |

Выбери **«Только семантика»**, для начала порог cosine **0.0** (чтобы видеть больше результатов), лимит 20. Затем поднимай порог, например до 0.5 и 0.7. При этом число найденных статей может уменьшаться.

**Не гарантируем** конкретные cosine scores, порядок при близких значениях или прохождение порога 0.5: всё зависит от реальной модели GigaChat и её эмбеддингов. Если даже при 0.0 нет совпадений, проверь фактические scores, доступность API и наличие векторов. `semantic_enabled=true` показывает лишь сконфигурированный адаптер, не гарантирует успешный сетевой запрос.

### Проверка Hybrid (weighted RRF)

- **Ключевые слова:** `самолёт`
- **Семантический запрос:** `Анализ медицинских снимков и помощь врачам`
- **Режим:** «Гибрид · RRF»
- **Порог cosine:** сначала 0.0
- **Лимит:** 20
- **Navec:** сначала выключен

Сравни настройки весов:

| BM25 | Embeddings | Что сравнить |
| ---: | ---: | --- |
| 0.8 | 0.2 | Больше влияние лексического ранжирования |
| 0.4 | 0.6 | Больше влияние семантического ранжирования |
| 0.2 | 0.8 | Преобладание семантического вклада |

**Это weighted RRF, не нейронный reranker.** Сумма весов должна быть равна 1. В карточке **показывается и итоговый RRF-score, и исходные BM25/cosine scores**. Значения RRF обычно малы (порядка 0.01), потому что используются обратные ранги с константой 60; это не вероятность. При таком запросе статья №1 имеет явный keyword-сигнал, а статья №2 тематически близка semantic-запросу — это хороший сценарий для сравнения, но перестановка результатов не гарантирована.

## Проверка метаданных и сохранения

- В карточке статьи должны независимо отображаться **Summary**, **Content**, **Теги**, **Опубликовано**, **Получено**. Для этих двух публикаций все три текстовых блока заполнены.
- `Опубликовано` ставится тестовым publisher **в момент POST** и передаётся как `pubDate` в RSS; `Получено` — момент загрузки статьи агрегатором. Даты могут различаться.
- Повторное **«Обновить»** тестовый RSS без новых публикаций должно возвращать `upserted=0` (идентичные GUID, без дубликатов).
- Измени ключевые слова и нажми **«Найти новости» без сохранения**: поиск использует текущую форму. Обнови страницу, заново выбери пользователя — должны вернуться ранее сохранённые фильтры.
- Для проверки `date_from` укажи **завтрашнюю дату** относительно момента получения: обе тестовые статьи должны исчезнуть из выдачи, поскольку фильтр применяется к `fetched_at` (а не `published_at`).
- Для проверки лимита с двумя совпадениями выставь **1**: в результатах должна быть одна карточка при `total=2`.

## Краткий чек-лист приёмки

- [ ] Две новости опубликованы через тестовый RSS
- [ ] Ручное обновление RSS перенесло обе новости в SQLite
- [ ] `аэрокварц` находит только №1; `медикварц` — только №2
- [ ] `врач` находит новость с `врачи`
- [ ] Две keyword-строки дают OR
- [ ] В карточках есть даты, Summary, Content и теги
- [ ] Navec показывает словарных соседей; расширение поиска объяснимо
- [ ] Semantic с низким порогом даёт результаты (при доступном GigaChat)
- [ ] Hybrid работает с разными весами, сумма весов равна 1
- [ ] Повторный refresh не создаёт дубликатов
- [ ] Несохранённые изменения участвуют в поиске, но не переживают перезагрузку

> Этот сценарий — **ручной тест-план**, а не отчёт о выполненных проверках. Отметь пункты после фактических действий в браузере.
