# RSS News Studio — новостной агрегатор (HSE NLP, HW2)

Локальное веб-приложение для сбора RSS/Atom-новостей и персональной фильтрации по **ключевым словам** и **семантическим темам**. Реализованы три уровня задания: keyword-поиск, semantic-поиск и независимые конфигурации для нескольких пользователей. В каждой найденной новости показываются причины совпадения и итоговая метрика ранжирования.

**[Оригинальное задание](hw2_task.md)** · **[Основа презентации (5 слайдов + демонстрация)](docs/presentation-outline.md)** · **[Сценарий демонстрации](docs/rss-test-scenarios.md)**

## Возможности

| Компонент | Реализация |
| --- | --- |
| RSS / Atom | `feedparser`, ручное добавление каналов, массовое/индивидуальное обновление, собственный тестовый RSS |
| Пользователи | Отдельные профили с фильтрами, темами, RSS-подписками и настройкой Navec |
| Keyword | BM25 + лемматизация русского языка (`pymorphy3`), опционально расширение Navec |
| Semantic | GigaChat Embeddings через `langchain-gigachat` + сохранённые векторы Qdrant |
| Hybrid | Взвешенное Reciprocal Rank Fusion (RRF), **не обученный reranker** |
| Интерфейс и API | HTML/CSS/JS, FastAPI, интерактивный Swagger |

Сервис — учебный MVP для локальной демонстрации, без Docker и внешнего сервера базы данных.

## Быстрый старт

Требуются Python **3.12+** и `uv`.

```bash
uv sync
cp .env.example .env
# Укажи GIGACHAT_AUTH_KEY, путь к Navec и при необходимости TLS-параметры в .env
uv run pytest -q
uv run ruff check .
uv run uvicorn news_aggregator.main:app --port 8000
```

- HTML: http://127.0.0.1:8000/
- Swagger: http://127.0.0.1:8000/docs
- Возможности поиска: http://127.0.0.1:8000/api/v1/capabilities
- Собственный RSS: http://127.0.0.1:8000/test-feed/rss.xml

**Все Python-зависимости входят в основной `uv sync`**, включая Navec, NumPy, GigaChat и Qdrant. Веса Navec (`models/navec_news.tar`) скачиваются отдельно и не хранятся в Git. Секретный `.env` не коммитить.

### Конфигурация

`main.py` читает корневой `.env`; полный список параметров — в [`.env.example`](.env.example).

```dotenv
NEWS_NAVEC_PATH=models/navec_news.tar
GIGACHAT_AUTH_KEY=
GIGACHAT_SCOPE=GIGACHAT_API_PERS
GIGACHAT_EMBEDDING_MODEL=Embeddings
GIGACHAT_VERIFY_SSL_CERTS=true
NEWS_EMBED_MAX_CHARS=2000
NEWS_POLL_INTERVAL_SECONDS=0
NEWS_LOG_LEVEL=INFO
```

Для GigaChat требуется действующий ключ и доступ к сети. Параметр `GIGACHAT_VERIFY_SSL_CERTS=false` отключает проверку сертификата; использовать лишь как временную локальную диагностику, предпочитая корректную цепочку доверия.

## Как работает приложение

```text
RSS/Atom
   ↓
RSS reader + feedparser
   ↓
RSS application service ───────→ SQLite: sources, articles, users, filters
   │
   └─ новые/изменённые статьи → GigaChat Embeddings → Qdrant

HTML/JS → FastAPI → SearchService
                      ├─ Keyword: pymorphy3 → BM25 (+ Navec)
                      └─ Semantic: embedding запроса → Qdrant cosine
                           ↓
                    Weighted RRF (в Hybrid)
                           ↓
                   объяснимая лента новостей
```

Код разделён на **application** (модели, сервисы и порты), **adapters** (RSS, SQLite, GigaChat, Qdrant) и **api/static**. Порты отделяют бизнес-сценарии от инфраструктуры.

При старте создаются таблицы SQLite и регистрируются **только отсутствующие** RSS: РИА Новости, Хабр — статьи, Коммерсантъ — Наука, МК — Наука и локальный тестовый RSS. **Скачивания новостей при старте нет.** Используй кнопку «Подтянуть все RSS» или «Обновить» у канала. При ручном добавлении RSS выполняется первоначальная попытка загрузки.

RSS обновляются асинхронно (до **3** одновременно). Для временных `ConnectTimeout` и `ReadTimeout` есть одна повторная попытка; ошибки отдельных каналов показываются пользователю, но остальные каналы продолжают обновляться. `NEWS_POLL_INTERVAL_SECONDS=0` отключает фоновый polling; положительный интервал включает его.

## Поиск и индексация

**Одна статья = один поисковый документ.**

- **BM25:** использует полный `title + summary + content + tags`; `pymorphy3` выполняет *лемматизацию*, а не простое отрезание окончаний. При каждом запросе для отобранных статей рассчитывается небольшой BM25-индекс. Поиск по нескольким keyword-фильтрам работает через OR, итоговый score — сумма BM25 по совпавшим фильтрам.
- **Navec:** опционально расширяет слова запроса близкими по векторному сходству терминами **из выбранного корпуса новостей**. Предпросмотр по словарю Navec не обязан совпадать с фактическим поисковым расширением.
- **Semantic:** при RSS refresh новые/изменённые статьи векторизуются из `title → tags → summary → content`, обрезанных до `NEWS_EMBED_MAX_CHARS` символов (по умолчанию 2000). Эмбеддинги сохраняются в `data/qdrant/`; при поиске считается **только вектор запроса**. Уже сохранённые статьи можно доиндексировать вручную через `POST /api/v1/search/index`.
- **Hybrid:** объединяет **ранги**, а не сырые BM25/cosine scores. Weighted RRF с константой 60; веса BM25/semantic настраиваются в интерфейсе (изначально 0.4/0.6). Итоговые scores порядка 0.01 нормальны и **не являются вероятностями**.

В карточке результата отображаются источник, дата публикации/получения, отдельные `summary`, `content`, теги, совпавшие слова, оценки фильтров и **итоговый `ranking_score`**. Параметры выдачи (режим, дата, лимит, порог cosine, веса гибрида) используются в текущем запросе. **Несохранённые изменения фильтров тоже участвуют в поиске**, но после обновления страницы загружается сохранённый профиль.

SQLite хранится в `data/news.db`; Qdrant — в `data/qdrant/`; публикации тестового RSS — в `data/test_feed.json`. После удаления SQLite прежние Qdrant-вектора могут остаться, но новые UUID новостей не будут использовать старые записи. Не удаляй данные без необходимости.

## Сценарий демонстрации

1. Открыть HTML, проверить RSS-каналы и обновить тестовый источник.
2. Создать/выбрать пользователя, задать ключевые слова, семантическую тему, отметить подписки.
3. Запустить Keyword, Semantic, Hybrid; показать объяснение и итоговый score.
4. Опубликовать статью в собственный RSS и **отдельно обновить** тестовый канал: публикация в XML не записывает статью напрямую в SQLite.
5. Повторить поиск и продемонстрировать появление новой статьи; при необходимости изменить фильтр без сохранения.

Для воспроизводимых тестовых запросов используй [приёмочный сценарий](docs/rss-test-scenarios.md). Внешние RSS могут временно отвечать с ошибкой; тестовый канал работает локально.
